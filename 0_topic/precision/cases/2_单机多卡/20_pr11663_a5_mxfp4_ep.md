# 案例 20：Ascend950 allgatherEP 下 MXFP4 topk_weights 被错误 cast 成 float8

> **一句话定位**：Ascend 950（A5）上 W4A8_MXFP4 MoE + allgatherEP 路径，原逻辑把 `topk_weights` cast 成与激活相同的 float8 dtype 再送 fused experts kernel——路由权重不该走 float8，输出错误。
>
> **对象**：vllm-project/vllm-ascend [PR #11663](https://github.com/vllm-project/vllm-ascend/pull/11663)（[Ascend950][Bugfix] Fix allgatherEP MXFPW4A8 quantization，merged 2026-07-10；cherry-pick v0.23.0 分支 #11718）

---

## 1. 问题描述

### 1.1 现象

- Ascend 950 硬件上 W4A8_MXFP4 量化 MoE + allgatherEP 推理输出错误（PR 原文："make W4A8_MXFP4 MoE inference work correctly"）；
- 根因：输入 dtype 为 `torch.float8_e4m3fn` 时，原逻辑将 `topk_weights` cast 成与 hidden states 相同的 float8——routing weights 不应被强转 float8 给下游 fused experts kernel。

### 1.2 触发条件（必现矩阵）

| 硬件 A5/950 | W4A8_MXFP4 | allgatherEP | 是否触发 |
|:---:|:---:|:---:|:---:|
| ✗ | — | — | ✗ |
| ✓ | ✗ | — | ✗ |
| ✓ | ✓ | ✗（TP-only） | ✗（不走该路径） |
| **✓** | **✓** | **✓** | **✓ 输出错误** |

### 1.3 影响与严重度

- **严重度**：🔴 高（A5 上 MXFP4 MoE EP 部署输出不可用）。
- **隐蔽性**：中（TP-only 路径正常，EP 才触发）。

## 4. 解决方案

### 4.1 根因

量化 kernel 的「路由权重系数」与「激活」dtype 策略不同——MXFP4 中 topk_weights 需保持 bf16 精度参与 fused experts，不能随激活一刀切 cast 成 float8。

### 4.2 修复内容

- **跳过 `topk_weights` 的 float8 cast**；
- 输入 dtype 为 `torch.float8_e4m3fn` 时启用 **bf16 兼容的 MXFP 执行模式**。

### 4.3 验证

正文未填具体测试项（随 A5 量化回归覆盖）。

## 5. 复现方法

### 5.1 最小复现模型

- 任一 **W4A8_MXFP4 量化的小 MoE 模型**（ModelSlim/MXFP4 导出）；需 **A5/950 硬件**。

### 5.2 复现命令

```bash
vllm serve <W4A8-MXFP4-MoE> --quantization ascend \
  --tensor-parallel-size 2 --enable-expert-parallel
# 与 TP-only（去掉 --enable-expert-parallel）输出对比即可见 allgatherEP 路径错误
```

---

## 核心教训

融合算子里「系数类张量（路由权重/scale）」与「数据类张量（激活）」的 dtype 策略必须分开——随激活一刀切 cast 是量化路径的常见静默精度坑；EP 与 TP 双路径要对拍。
